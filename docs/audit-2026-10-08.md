# QA Lab: báo cáo rà soát và cách xử lý lỗi

Ngày kiểm tra: 08/10/2026. Phiên bản code: **1.1.1**.

## 1. Đọc kết quả thế nào cho đúng?

**Test FAIL không đồng nghĩa với web bị bug.** Có ba khả năng khác nhau:

1. Test cố ý tạo điều kiện vượt giới hạn. Ví dụ Stress làm API đầy 24 công việc và trả 503. Web đo đúng, nhưng yêu cầu hiệu năng không đạt ở mức tải đó.
2. Web xử lý sai. Ví dụ nhận `false` như số 0 rồi kết luận PASS, hoặc vẫn hiện PASS của dữ liệu cũ sau khi đã đổi đầu vào. Những lỗi này phải sửa code.
3. Một thành phần bên ngoài không đáp ứng. Ví dụ Gemini hết quota, máy thiếu k6, trình duyệt từ chối truy cập localhost, hoặc GitHub giới hạn API. Cần xử lý đúng thành phần đó; không phải cứ sửa giao diện là hết.

**PASS** = kết quả thực tế khớp điều kiện được ghi trong bảng. **FAIL** = không khớp. **INVALID** = đầu vào không hợp lệ. **NOT RUN** = chưa chạy với đầu vào hiện tại. **NOT VERIFIED** = chưa có bằng chứng thực thi. **INCOMPLETE** = chưa lấy đủ dữ liệu để kết luận toàn bộ. Không được viết NOT RUN/NOT VERIFIED/INCOMPLETE thành PASS trong báo cáo nộp thầy.

Không thể liệt kê trước tuyệt đối mọi lỗi của mọi máy, mạng và dịch vụ. Tài liệu này ghi những lỗi đã tìm thấy và các tình huống thực tế quan trọng cần phòng ngừa, kèm cách phân biệt nguyên nhân.

## 3. Kết quả kiểm tra

### 3.1 Bộ test tự động

Lệnh `npm run test:all` kết thúc exit 0: **69 unit + 21 API + 50 browser = 140 test PASS**. Bộ browser có 6 lượt skip theo cấu hình: hai test k6 thật trên hai projects chỉ bật thủ công (4 lượt), case mobile-only ở desktop (1 lượt), baseline desktop-only ở mobile (1 lượt). Hai test k6 thật đã được chạy riêng trên desktop và đạt, tổng cộng 5 scenario runs thật. Không tính các case bị skip là PASS.

Test được chạy bằng server mới trên port 4187, không tái sử dụng server cũ đang chạy trên máy. Kiểm tra `npm audit --json` sau cập nhật trả **0 vulnerabilities đã biết**. Ảnh kết quả local được giữ trong `outputs/qa-audit-2026-10-08` ở workspace, không đưa key/file cá nhân vào repo.

Các case Gemini dùng **provider giả lập**, không sử dụng key thật và không phát sinh phí Gemini. Chúng kiểm tra code nhận lỗi, phân loại lỗi và hiện đúng trên giao diện; chúng không chứng minh tài khoản/key của một người dùng cụ thể hoạt động.

### 3.3 Những giới hạn chưa được chứng minh

- Chưa gọi Gemini thật bằng key của bạn trong đợt kiểm tra này. Không thể chốt nguyên nhân của ảnh 502 cũ chỉ từ một mã HTTP chung.
- Không thể tự xác nhận người dùng đã bấm Allow trong mọi trình duyệt/chính sách Windows. API bridge được test đúng origin/token; việc trình duyệt cho mở app là quyền của người dùng.
- Mobile được kiểm tra bằng Chromium mô phỏng điện thoại và màn hình hẹp, không phải chứng nhận native Android/iOS hoặc mọi điện thoại thật.
- Soak vài phút chỉ là minh họa. Không đủ để khẳng định không có memory leak trong nhiều giờ/ngày.
- Chưa kiểm tra Firefox/Safari, máy ARM, mọi bản Windows hoặc mọi firewall/antivirus.
- npm audit không có cảnh báo đã biết không có nghĩa là app không thể có lỗ hổng.

## 4. Performance: cách chạy, PASS/FAIL và lỗi có thể gặp

### Cách chạy

1. Mỗi thành viên tải repo mới, giải nén vào thư mục cố định, chạy `setup-windows.cmd` một lần.
2. Mở site hosted, bấm **Connect k6**, chấp nhận mở QA Lab và quyền local network nếu trình duyệt hỏi. Có thể dùng trang localhost từ `start-windows.cmd` để tránh quyền kết nối từ site hosted.
3. Chọn Load/Stress/Spike/Soak, nhập Local peak VUs, bấm **Run local k6**. Chờ trạng thái completed, đọc bảng trực tiếp trên web.
4. Đối chiếu scenario, Run ID, thời điểm hoàn thành trước khi chụp bằng chứng. Không lấy kết quả nhập từ file cũ làm kết quả của lần mới.

**Run probe** chỉ gửi một request. Nó cho biết API có đáp ứng, work factor và thời gian của request đó; không đo error rate/p95 của hàng nghìn requests, không thay thế k6. Work factor 1 = 1.000 lần PBKDF2; 100 = 100.000 lần. Không thể hứa work 100 sẽ mất một số ms cố định vì còn CPU, hàng đợi và tải nền.

### Value quyết định

| Value | Ý nghĩa dễ hiểu | PASS/FAIL |
|---|---|---|
| VUs | Số người dùng ảo chạy đồng thời theo kịch bản | Là đầu vào tải, không tự quyết định PASS |
| p95 | Khoảng thời gian mà 95% request không chậm hơn | PASS khi **nhỏ hơn** limit; bằng limit cũng FAIL |
| Error rate | Phần trăm request k6 coi là thất bại | PASS khi **nhỏ hơn** error limit |
| Successful response contract | Số HTTP 200 có body sai hợp đồng | Phải bằng 0 |
| Exported k6 thresholds | Các quyết định mà chính k6 xuất ra | Không được có threshold FAIL |
| k6 exit code | Kết quả tiến trình k6 | 0 = đạt; 99 thường là vượt threshold; mã khác cần kiểm tra tiến trình |
| Requests/RPS | Số request và số trung bình mỗi giây | Dùng mô tả throughput; app không đặt ngưỡng RPS PASS riêng |
| HTTP 503 | Request bị từ chối khi hàng đợi đầy | Làm tăng error rate; không mặc nhiên là code crash |
| HTTP 200 p95 | p95 chỉ của request thành công | Dùng kiểm tra latency mà không bị 503 trả nhanh làm giảm số đo |
| Active/peak active | Công việc server đang xử lý/đỉnh đã quan sát | Không phải số VUs; mặc định tối đa 24 |
| Node heap | RAM heap của tiến trình Node | Không có ngưỡng tự kết luận memory leak |
| Phase comparison | p95/errors theo từng giai đoạn | Phase có thể FAIL dù trung bình toàn test PASS; cần giải thích cả hai |

| Kịch bản | p95 limit | Error limit | Thời gian mặc định |
|---|---:|---:|---:|
| Load | 300 ms | 1% | 17 giây |
| Stress | 900 ms | 15% | 34 giây |
| Spike | 1.000 ms | 15% | 22 giây |
| Soak | 500 ms | 1% | 100 giây: ramp 5 + steady 90 + ramp-down 5 |

Các limit này là quy tắc của bài demo, không phải chuẩn bắt buộc cho mọi ứng dụng.

Nếu cần Soak dài hơn, đặt `SOAK_STEADY` trước khi khởi động server/CLI. Ví dụ PowerShell:

```powershell
$env:SOAK_STEADY='3m'
npm start
```

Lúc này steady là 180 giây, tổng kế hoạch là 190 giây. Sau khi demo có thể đóng server, bỏ biến môi trường đó và khởi động lại để trở về 90 giây steady. Không cần thay code. Nếu kết nối từ trang hosted, biểu đồ của hosted vẫn là config của hosted; biểu đồ localhost mới phản ánh cấu hình local tùy chỉnh.

## 5. Unit

**Đang test gì:** hàm quyết định threshold, không tạo tải và không tự đo server. Bạn nhập số quan sát và limit để kiểm tra logic.

**Chạy:** chọn Unit, điền p95/errors/limits, bấm Evaluate. Run key cases chạy 12 case mẫu trong browser; bộ Vitest còn kiểm tra sai kiểu dữ liệu và các hàm khác.

**Expect PASS:** p95 nhỏ hơn limit và error rate nhỏ hơn limit. Ví dụ 280 ms < 500 ms, 0,5% < 1%.

**FAIL:** p95 500 với limit 500, hoặc errors 1% với limit 1%. **INVALID:** số âm, trống, sai kiểu, error rate ngoài 0–100% hoặc limit không hợp lệ. Case kiểm thử boundary vẫn PASS khi hàm trả FAIL đúng như expected; không nhầm hai lớp kết quả này.

| Lỗi có thể gặp | Nguồn | Fix/retest |
|---|---|---|
| Nhầm 1 với 1% | UI dùng %, API dùng tỷ lệ 0..1 | Trên UI nhập 1 là 1%; gọi API thì 1% = 0.01 |
| Bằng limit vẫn mong PASS | Hiểu sai quy tắc strict `<` | Xem Expected/limit; thử giá trị sát dưới, bằng, sát trên |
| PASS dù gửi false/[] | Bug ép kiểu của bản cũ | Đã sửa; `/api/evaluate` phải trả 400 |
| Sửa số nhưng còn PASS cũ | Kết quả chưa tính lại | Bản mới đưa về NOT RUN; bấm Evaluate |

## 6. API

**Đang test gì:** mã HTTP, JSON và các field đúng hợp đồng. Response time được đo nhưng ở topic này chưa có limit latency riêng.

**Chạy:** chọn preset, sửa JSON nếu cần, bấm Send request. Xem Expected/Observed/Result của từng dòng.

| Case | Expected để test PASS |
|---|---|
| Health | 200, JSON, service=qa-lab, status=ready |
| Metrics | 200, completed và capacity là số hữu hạn |
| Evaluate valid | 200, valid=true, passed là boolean |
| Evaluate invalid | 400, có field error p95Ms |
| Route missing | 404, error=not_found |

**Lưu ý:** evaluate valid trả `passed=false` vẫn có thể là API test PASS nếu hợp đồng chỉ yêu cầu boolean và trả đúng 200. Muốn kiểm tra threshold đạt hay không thì xem Unit/Performance. Không đánh đồng HTTP 200 với toàn bộ nghiệp vụ PASS.

| Lỗi có thể gặp | Nguồn | Fix/retest |
|---|---|---|
| 400 invalid_json | JSON sai dấu phẩy/ngoặc/quote | Sửa JSON; body sai không phải server crash |
| 413 body_too_large | Vượt 16 KB guardrail | Giảm body; không bỏ limit chỉ để một request lớn đi qua |
| 404 not_found | Gõ sai endpoint hoặc đúng case missing | Đối chiếu preset/contract; nếu expected 404 thì PASS |
| 500 internal_error | Lỗi bên trong QA Lab | Ghi endpoint, thời gian, input không chứa secret; tái hiện trên local và sửa code |
| HTML thay JSON | Deploy sai service/build hoặc proxy/error page | Kiểm tra URL `/api/health`; app mới trả JSON cho lỗi API của chính nó |
| Request failed | Mất mạng, target tắt, DNS, timeout | Kiểm tra health và console Network; không kết luận lỗi schema khi chưa có response |
| Đổi body nhưng còn verdict cũ | Bug/stale UI của bản cũ | Đã reset về NOT RUN; gửi lại request |

## 7. Web E2E

**Đang test gì:** cả chuỗi nhập -> validate -> review -> save -> gọi API -> lấy lại dữ liệu. Đây là một chức năng nhỏ làm đối tượng kiểm thử, không phải app quản lý giao task.

**Value quan trọng:** HTTP save=201; read-back=200; ID, tên, scenario, VUs, notes phải trùng dữ liệu đã gửi sau chuẩn hóa. Mới Review chỉ là VALIDATED, chưa E2E PASS.

**Chạy:** tên 3–40 ký tự; scenario Stress/Spike/Soak; Peak VUs 1–50; notes tối đa 200 ký tự. Review, Back để thử sửa, rồi Save.

| Lỗi có thể gặp | Nguồn | Fix/retest |
|---|---|---|
| Form không cho Review | Validation đúng: tên ngắn/số VUs sai | Sửa field được đánh dấu; test invalid PASS khi bị chặn đúng |
| Save 201 nhưng GET khác ID/notes | Bug lưu/đọc hoặc response sai | Bảng E2E phải FAIL; kiểm tra API lưu/đọc và mapping field |
| GET 404 sau restart | Plan nằm trong RAM, không có database | Tạo plan mới; đây là giới hạn đã công bố. Nếu cần bền vững mới thêm database |
| Plan cũ biến mất sau nhiều lần tạo | Chỉ giữ tối đa 100 plan/instance | Không dùng làm lưu dữ liệu lâu dài; có thể test giới hạn này |
| Save thành công nhưng GET lúc được/lúc không trên nhiều instances | RAM không được chia sẻ giữa instances | Demo một instance; muốn scale cần shared persistence, không chỉ refresh browser |
| Back rồi đổi dữ liệu nhưng vẫn thấy PASS | Evidence cũ | Bản mới reset và yêu cầu review/save lại |

## 8. Mobile web

**Đang test gì:** web responsive ở viewport hiện tại, không phải app APK. Chromium mobile có giả lập kích thước/touch nhưng không thay test điện thoại thật.

**Chạy:** mở Mobile web, bấm Check layout; để demo mobile dùng browser device mode hoặc điện thoại. Open plan flow rồi thực hiện E2E ở cùng width, quay lại Mobile để đọc dòng workflow.

**Value quyết định layout PASS:** horizontal overflow=0 px; control được đo có width và height ít nhất 24 px. Touch points chỉ INFO. Dòng mobile workflow có PASS/FAIL/NOT RUN riêng; layout PASS không chứng minh workflow hay native behavior PASS.

| Lỗi có thể gặp | Nguồn | Fix/retest |
|---|---|---|
| Overflow > 0 | CSS/layout hoặc zoom/viewport không đúng | Kiểm tra phần tử quá rộng; sửa responsive rồi test 360/412 px |
| Target quá nhỏ | CSS button/spacing | Tăng vùng tương tác; không chỉ phóng chữ |
| Touch not detected trên laptop | Thiết bị không có touch | Không phải bug; dùng phone/emulation, vẫn đọc INFO đúng |
| Workflow NOT RUN sau đổi width | Bằng chứng workflow thuộc width cũ | Chạy lại E2E ở width mới |
| Native Appium test không áp dụng | App là mobile web | Nếu thầy yêu cầu native phải có app riêng; không ghi đã test Android/iOS native |

## 9. Visual regression

**Đang test gì:** pixel/layout thay đổi so với reference, không phải số liệu thật của performance. Các số 184 ms/0,3%/99,9% trong specimen là nội dung cố định để so ảnh.

**Chạy:** chọn Baseline và Compare images, rồi Shifted variant. Bản shifted di chuyển heading 28 px, phải bị phát hiện FAIL; chuyển Baseline lại phải PASS.

**Value quyết định trên web:** kích thước ảnh phải giống; tỷ lệ pixel đổi không quá 0,1%; chênh channel hơn 16/255 được tính là đổi. Playwright có baseline file và tolerance riêng cho bộ test của nó; không đánh đồng hai thuật toán so ảnh.

| Lỗi có thể gặp | Nguồn | Fix/retest |
|---|---|---|
| Baseline FAIL trên OS/browser khác | Font/rendering/scale khác hoặc CSS thật thay đổi | Giữ môi trường Chromium/Windows đồng nhất; xem diff trước khi update baseline |
| Image dimensions differ | Width/zoom không đồng nhất | Chụp baseline và actual cùng viewport/scale |
| Compare ERROR | Canvas/library/font chưa tải hoặc browser policy | Kiểm tra vendor asset/network, reload; không coi ERROR là PASS |
| Shifted PASS | Ngưỡng quá lỏng hoặc comparator/baseline sai | Test shifted cố ý phải FAIL; chỉ update baseline sau review thay đổi đúng |
| Screenshot suite fail do thay đổi chủ đích | Expected regression demonstration | Tách `test:demo-failures` khỏi bộ test bình thường |

## 10. AI-assisted: phân biệt web lỗi hay Gemini lỗi

**Đang test gì:** khả năng lấy draft từ Gemini và review đề xuất. App không tự chạy code Gemini sinh ra. Check đủ 4 ô chỉ là xác nhận của con người, không phải bằng chứng code đã PASS.

**Chạy:** My API key -> nhập key API hợp lệ -> Load models -> chọn model -> Generate test cases. Hoặc Group API với group access code khi owner đã cấu hình server. Không nhập mật khẩu Google thay API key. Không đưa secret vào screenshot/repo.

**Đường đi của request:** browser -> QA Lab server -> Gemini API -> QA Lab -> browser. Vì có hai server, QA Lab 502 không nhất thiết nghĩa là Gemini 502.

Ví dụ: bảng ghi **Generation HTTP 502**, **Failure source Gemini API**, **Gemini HTTP 404**, **ai_model_unavailable**. Khi đó QA Lab đã nhận lỗi model/endpoint từ Gemini và chuyển thành 502; hãy Load models/chọn lại model. Không kết luận server Google sập chỉ từ 502.

| Mã/hiện tượng | Nguyên nhân có thể | Ai/cái gì cần xử lý? |
|---|---|---|
| QA Lab 400 invalid_ai_request | Topic sai, requirement <10 hoặc >500 | Người dùng sửa input; app validate đúng |
| QA Lab 400 invalid_model | ID không đúng định dạng Gemini | Chọn model từ danh sách, không nhập path/link |
| QA Lab 403 ai_access_denied | Group code sai, personal key quá ngắn/sai định dạng | Kiểm tra credentials trước khi gọi Gemini |
| QA Lab 503 ai_not_configured | Group mode thiếu biến GEMINI_API_KEY hoặc AI_DEMO_ACCESS_CODE | Owner cấu hình server hoặc dùng personal key |
| Gemini 400 + API_KEY_INVALID | Key không hợp lệ | Key/project Google; tạo/kiểm tra key đúng |
| Gemini 401/403 | Key hết hạn/bị chặn/restrictions, API chưa enable, project không có quyền | Chủ key kiểm tra AI Studio/Cloud và quyền API; không mặc định blame web |
| Gemini 404 | Model/endpoint không khả dụng hoặc quyền truy cập | Load models, chọn model phù hợp. Nếu mọi model đều lỗi, kiểm tra API version/request code |
| Gemini 400 không có key reason | Cấu hình request/model/project/region | Có thể do app gửi tham số không hỗ trợ, không chỉ do Google. Đối chiếu request contract và thử model khác |
| Gemini 402/billing reason | Credits/billing API project | Chủ project xử lý; không phải lỗi CSS/frontend |
| Gemini 429, QA Lab 503 ai_quota | Quota request/token của Gemini | Chờ, xem quota của API project, giảm số lần/token; không bấm liên tục |
| QA Lab 429 ai_rate_limit, source QA Lab protection | App dùng hết 20 generation/giờ hoặc 30 model-list/giờ, hay đang có 2 calls | Chờ Retry-After; đây là giới hạn app, không phải provider quota |
| Gemini 408/500/503 | Provider timeout/dịch vụ lỗi tạm thời | Chờ, thử model khác, kiểm tra Gemini service status |
| ai_timeout, không có provider HTTP | Timeout đường QA Lab->Gemini | Có thể mạng hoặc model chậm; không đủ bằng chứng key sai |
| ai_unavailable, không có provider HTTP | Server không kết nối được: DNS/firewall/internet | Kiểm tra mạng của server host, không chỉ wifi của browser |
| Browser No response | Browser->QA Lab không hoàn tất | Render đang restart, mạng browser, timeout; kiểm tra health trước khi blame Gemini |
| Gemini 200 nhưng ai_content_blocked | Safety/recitation/content filter | Đổi requirement sang nội dung test trung tính; không tắt safety |
| Gemini 200 nhưng ai_empty_response | Không có final text hoặc chỉ thinking | Requirement ngắn hơn/model nhanh hơn; nếu lặp nhiều cần kiểm tra budget/parser |
| ai_bad_response | Provider không trả JSON/schema đúng | Retry; nếu thường xuyên cần rà parser tương thích provider |
| Draft truncated WARNING | Hết budget token hoặc quá giới hạn hiển thị | Không chạy code bị cắt; yêu cầu draft ngắn hơn, review nội dung |
| Draft sinh sai endpoint/assertion | AI hallucination hoặc requirement mơ hồ | So contract thật và sửa test trước khi chạy; không gọi là test PASS |
| Draft cũ còn hiện sau đổi model/requirement | Bug quản lý UI state | Đã sửa; bản mới xóa draft cũ và checklist |

**Cách kiểm tra một lỗi AI cụ thể:** ghi thời điểm, model đã chọn, Generation HTTP, Failure source, Gemini HTTP, provider code/reason và Suggested action. Không ghi API key/access code. Nếu không có upstream response thì ghi “chưa đủ dữ liệu kết luận provider lỗi”.

App không tự retry generation để tránh gọi trùng và phát sinh chi phí. Việc có Gemini Pro trong app chat không thay cho key/quota API của project. Bản này dùng API key, không có Google OAuth login.

## 11. CI/CD và reporting

**Đang test gì:** pipeline GitHub Actions install -> unit/API -> browser desktop/mobile -> xuất report khi fail. Bấm Refresh results chỉ đọc workflow thực tế trên GitHub, không tự push hoặc tự chạy một workflow mới.

**Value quyết định:** workflow/job/step status và conclusion, commit SHA, branch. PASS toàn bộ chỉ khi dữ liệu đầy đủ, không có fail/pending; conditional step SKIPPED không tự làm workflow FAIL.

| Lỗi có thể gặp | Nguồn | Fix/retest |
|---|---|---|
| Workflow/job/step failure | Test thật thất bại, npm/install/browser fail | Mở Actions, xem step/log, tái hiện local, sửa nguyên nhân rồi push |
| GitHub 403/429/Unavailable | API rate limit, mạng hoặc quyền truy cập | Chờ, mở Actions trực tiếp; app không được lấy kết quả cũ và giả PASS |
| Workflow success nhưng jobs unavailable | Thiếu bằng chứng chi tiết | Bản mới ghi INCOMPLETE, không PASS tổng |
| Commit không trùng code vừa tải | Đang đọc workflow cũ hoặc branch khác | Đối chiếu SHA/branch; đợi run mới xong |
| Workflow pending/cancelled/timed_out | GitHub runner queue, cancel hoặc quá timeout | Không ghi PASS; kiểm tra Actions và rerun đúng commit |
| Deploy Render cũ dù CI mới | CI không đồng nghĩa deploy, auto-deploy/root/branch/cache cấu hình sai | So `/api/version`, commit và dashboard deploy |

## 12. Lỗi cài đặt/cập nhật/deploy chung

| Hiện tượng | Nguồn | Cách xử lý |
|---|---|---|
| Node.js/npm required | Thiếu Node hoặc PATH chưa cập nhật | Cài Node 20+, mở terminal mới, chạy setup lại |
| Node <20 | Runtime quá cũ | Cập nhật Node, kiểm tra `node --version` |
| npm ci failed | Internet/proxy/registry hoặc lock/dependencies sai | Kiểm tra log; dùng repo đầy đủ bản mới; không trộn package.json bản mới với lock bản cũ |
| Playwright browser missing | Chưa tải browser test | Chạy `npx playwright install chromium`; không cần bước này chỉ để xem web/chạy k6 |
| Port already in use | App cũ hoặc phần mềm khác | Xác định tiến trình, tắt đúng server của mình hoặc dùng PORT khác cho local page |
| Web vẫn code cũ sau tải bản mới | Node process cũ chưa restart | Dừng đúng server cũ, chạy setup/start bản mới; không chỉ refresh browser |
| qalab connector trỏ folder cũ | Di chuyển/xóa folder sau setup | Chạy setup tại folder sẽ giữ cố định |
| Windows SmartScreen/antivirus | Chính sách máy hoặc file tải từ mạng | Kiểm tra nguồn GitHub trước; không tắt antivirus toàn máy để chạy demo |
| Render chưa lên bản mới | Chưa push/deploy lỗi/chọn nhầm branch hoặc root | So version+commit, xem build log, deploy commit đúng |
| Render restart làm mất plan/results | Dữ liệu RAM theo instance | Hành vi đã nêu; chạy lại demo. K6 results ở máy local không được gửi lên Render |
| Public web chạy nhưng local k6 không có dữ liệu | Chưa connect; hai backend khác nhau | Bấm Connect k6; số telemetry khi connected phải thuộc Local Node process |

### Cập nhật bản mới an toàn

1. Ghi lại các cấu hình cá nhân cần dùng, không đưa secret vào GitHub.
2. Đóng đúng server QA Lab cũ. Không xóa bài/file khác trên máy.
3. Tải GitHub ZIP bản mới và giải nén riêng; hoặc dùng `git pull --ff-only` nếu bản clone sạch. Nếu có tự sửa code, commit/backup trước, không dùng `git reset --hard`.
4. Chạy `setup-windows.cmd` trong folder mới để cài dependency theo lockfile và sửa đường dẫn connector.
5. Start local hoặc Connect k6 lại. Kiểm tra dòng **Version 1.1.1** và `/api/version`.
6. Run Load để thấy một bảng mới trước khi thử Stress/Spike/Soak.

## 13. Danh sách test đã bao phủ

Mã test nằm trong repo để cả nhóm chạy lại, không cần tin vào ảnh chụp:

- `tests/unit/lab-rules.test.js`: strict threshold dưới/bằng/trên; phối hợp latency/errors; sai kiểu boolean/array/object/blank/null/Infinity; số scientific; percentile; plan normalization/boundaries; Soak duration s/m/h/ms và invalid; shapes/scaling/limits của load profiles.
- `tests/unit/test-evidence.test.js`: quyết định từ summary, ngưỡng thực tế, contract failure, export threshold, exit code, pixel diff và bridge URI/session. Xem từng tên case trong file cho assertion chính xác.
- `tests/unit/ai-assistant.test.js`: 9 nhóm HTTP provider; invalid key qua HTTP 400; timeout/abort/network; default parameters; bỏ reasoning; safety block; empty/null draft; JSON hỏng; truncated output; pagination/dedup/malformed entries/loop/model-list failure.
- `tests/api/app.test.js`: version/commit/no-store; bridge origin/token/preflight; local-only run; health/profile/catalog; PBKDF2/telemetry; invalid work; 24-job saturation; production rate limit; metric/plan validation; malformed/oversized JSON; safe internal errors; group/personal AI auth; generation limits; model-list limits; safe diagnostics; configured Soak duration.
- `tests/e2e/workflows.spec.js`: scenario/probe/VUs; summary import/schema; run mới thay run cũ; hosted guard; unit/API; plan review/back/save; visual variant; AI prompt/generate/text safety/personal key; mobile navigation.
- `tests/e2e/evidence.spec.js`: 12 unit key cases và expected vs actual; không ghi đè scenario bằng run cũ; API field/status decisions; visual pixel baseline/shift/recovery; read-back sai ID/notes FAIL; CI failed jobs/steps; AI request lỗi xóa draft cũ.
- `tests/e2e/audit-regressions.spec.js`: safe provider diagnostics hiển thị; input invalidation; pending controls; API edits; probe overlap; CI incomplete/contradictory jobs; overflow/touch-target FAIL có chủ đích; cả 8 topic ở 360 px; screenshots evidence desktop/mobile.
- `tests/e2e/visual.spec.js`: screenshot baseline thật; shifted demonstration cố ý FAIL và được tách khỏi test bình thường.
- `tests/e2e/real-k6.spec.js`: bấm nút thật chạy Load/Stress/Spike/Soak; Run ID mới, on-page result, exit code; long Soak kiểm tra đơn vị phút/phase và không bị giết sau 180 giây. Các test thật chỉ bật thủ công, không chạy load trên CI/Render.
